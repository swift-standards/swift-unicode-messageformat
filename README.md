# swift-unicode-messageformat

Use this package when a message has placeholders, plurals or other variants and must read well in every language: declare it once as a `Message`, such as `".input {$count :number} .match $count one {{{$count} app}} * {{{$count} apps}}"`, and `apps(["count": 3], in: .en)` gives "3 apps". It implements Unicode MessageFormat 2.0 as published in Part 9 of UTS #35 for CLDR 49 (LDML 49): the syntax, the data model, pattern selection with plural categories from swift-unicode-cldr, formatting with the default bidi strategy, and the REQUIRED functions `:string`, `:number`, `:integer` and `:offset`. A locale is a `BCP47.LanguageTag`. The tests run the specification's own conformance suite from CLDR 49 (`common/testData/messageFormat/tests` at the `release-49` tag of `unicode-org/cldr`), held in the tests under the Unicode License v3, whose notice travels with it.

## Laws

- A message is read by the ABNF of UTS #35 Part 9. Text that does not match throws `Message.Error.syntax` with the offset, in Unicode scalars, where reading stopped.
- A well-formed message that is not valid throws its data model error from `Message(parsing:)`: a duplicate declaration, including a variable used before it is declared or in its own declaration; a duplicate option name; a variant whose key count differs from the selector count; a missing all-`*` variant; a selector whose declaration chain reaches no function; or a duplicate variant, where literal keys are compared by canonical equivalence.
- A message written as a string literal is read when it is declared, and one that is not well-formed and valid stops the program. `Message(parsing:)` throws instead.
- Formatting never fails. Every error found while resolving, selecting or formatting is returned in `Message.Output.errors`, and a placeholder that cannot be resolved or formatted shows its fallback in braces, such as `{$name}`, `{|42|}` or `{:ns:fn}`.
- Declarations are resolved when first used and at most once. Errors in a declaration or a variant that is never used are not reported.
- `:number`, `:integer` and `:offset` select an exact numeric key first, then the CLDR plural category of the rounded value, cardinal or, with `select=ordinal`, ordinal; `select=exact` uses exact keys only. A key that is neither a number literal nor a plural category is a bad variant key. `select` must be a literal, and a `select` inherited from an operand is refused, which makes the value unselectable.
- `:number` accepts every REQUIRED option of the specification and rounds half away from zero by default. `:integer` rounds its operand half away from zero, and `:offset` takes exactly one of `add` and `subtract`. A number operand inherits the options of an operand that is itself a number, the options on the expression winning.
- `:string` selects by canonical equivalence with the key and formats its operand unchanged. Given an operand that failed to resolve, it formats as that fallback and matches no key, without a further error.
- An unannotated variable holding a number formats as `:number` would. A literal without a function is a string.
- The default bidi strategy isolates each placeholder: numbers carry the direction of their locale from `CLDR.direction(in:)`, strings carry none, and `u:dir` sets a direction and forces isolation. `Message.Isolation.disabled` turns isolation off.
- `u:id` is carried into the formatted parts, `u:dir` on markup is a bad option, and attributes have no effect on the result.
- `Message.Output.parts` holds text, formatted values with their direction and id, markup with its options, fallbacks and isolation marks, and its text is the formatted string. Markup formats as the empty string.
- Functions are looked up by name in `Message.Functions`. `adding(_:_:)` registers a user-defined `Message.Handler`, and a name with no handler is an unknown function.
- The conformance suite passes in full: its 416 tests in `syntax`, `syntax-errors`, `data-model-errors`, `fallback`, `pattern-selection`, `bidi`, `u-options` and `functions/string`, `number`, `integer` and `offset`, with the suite's `:test:function`, `:test:select` and `:test:format` registered as user functions. The RECOMMENDED `:currency` and `:percent` and the Draft date, time and unit functions are not provided, and their suites are not included.
